## 1. 현황 파악 체크리스트

저장소 URL을 공유해 주시면 즉시 실제 구조를 분석합니다.  
그 전까지 확인해야 할 항목은 아래와 같습니다.

| 확인 항목 | 체크 | 비고 |
|---|---|---|
| 저장소 URL (public/private) | ☐ | private이면 토큰 필요 |
| 데이터 포맷 (CSV / JSON / YAML / SQL) | ☐ | 포맷별 파이프라인 다름 |
| 데이터 규모 (행 수 / 파일 수 / GB) | ☐ | 소규모 vs 대규모 전략 분기 |
| 업데이트 주기 (정적 / 주기적 갱신) | ☐ | CI 자동화 여부 결정 |
| 라이선스 (MIT / CC / 사유) | ☐ | 상업 서비스 가능 여부 |
| 컬럼 정의 (README 또는 schema 파일) | ☐ | 매핑 설계 기준 |
| 관계 테이블 유무 (객실 / 가격 / 사진) | ☐ | 정규화 수준 판단 |

## 2. 데이터 구조 유형별 시나리오

[추정] 호텔 깃허브 데이터는 보통 아래 3가지 형태 중 하나입니다.

### 시나리오 A — 단순 CSV/JSON (가장 흔함)
```
hotels.csv
  id, name, address, lat, lng, star, price_min, amenities
```
- **적용 난이도**: ⭐⭐ (쉬움)
- **전략**: 1회성 import → DB 테이블화 → API 서빙

### 시나리오 B — 다중 테이블 구조
```
/data
  hotels.json
  rooms.json
  reviews.json
  images.json
```
- **적용 난이도**: ⭐⭐⭐ (중간)
- **전략**: 관계 정의 → 정규화 → ORM 모델 설계

### 시나리오 C — 스크래핑 원본 데이터 (비정형)
```
/raw
  booking_crawl_20240101.json
  naver_hotel_20240201.json
```
- **적용 난이도**: ⭐⭐⭐⭐ (어려움)
- **전략**: 전처리 파이프라인 → 정규화 → 검수 → 적재

| 작업 | 담당 | 도구 |

### Phase 2 — 데이터 정제 (Day 3~7)

```python
# 정제 작업 예시 (Python)
import pandas as pd

df = pd.read_csv('hotels.csv')

# 결측치 처리
df['price_min'].fillna(df['price_min'].median(), inplace=True)

# 좌표 유효성 검증 (한국 범위)
df = df[
    (df['lat'].between(33.0, 38.9)) &
    (df['lng'].between(124.6, 132.0))
]

# 중복 제거
df.drop_duplicates(subset=['name', 'address'], inplace=True)

df.to_csv('hotels_clean.csv', index=False)
```

주요 정제 항목:
- [ ] 결측치(누락 주소, 좌표, 등급) 처리
- [ ] 중복 항목 제거
- [ ] 좌표값 유효성 검증 (Kakao 지도 API 역지오코딩 교차 확인)
- [ ] 가격·날짜 데이터 타입 통일

### Phase 3 — DB 적재 (Day 8~9)

**권장 DB 구조** (PostgreSQL 기준)

```sql
-- 호텔 마스터 테이블
CREATE TABLE hotels (
    id          SERIAL PRIMARY KEY,
    name        VARCHAR(200) NOT NULL,
    address     TEXT,
    lat         DECIMAL(10,7),
    lng         DECIMAL(10,7),
    star_grade  SMALLINT,          -- 1~5
    price_min   INTEGER,           -- 원 단위
    amenities   JSONB,             -- 유연한 부가정보
    source_url  TEXT,              -- 원본 출처
    created_at  TIMESTAMP DEFAULT NOW(),
    updated_at  TIMESTAMP DEFAULT NOW()
);

-- 공간 인덱스 (지도 검색 성능)
CREATE INDEX idx_hotels_location
    ON hotels USING GIST (
        ll_to_earth(lat, lng)
    );
```

## 5. 깃허브 → 운영 DB 자동 동기화 (선택 옵션)

저장소 데이터가 주기적으로 업데이트된다면:

```yaml
# .github/workflows/sync.yml
name: Sync Hotel Data
on:
  schedule:
    - cron: '0 2 * * *'   # 매일 새벽 2시
  push:
    paths: ['data/hotels*']

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Run ETL
        run: python etl/load_hotels.py
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
```

**효과**: 깃허브 push 또는 스케줄에 따라 DB 자동 갱신 → 수동 관리 제로화
