# 라우팅 규칙

## 1차 라우팅 — 본부장 → 4팀장

| 작업 성격 | 1차 담당 | 비고 |
|----------|---------|------|
| 조사·자료 수집·시장 분석·법령 조사·기업 신상 조사 | 기획팀장 | WebSearch · Naver · Apify · opendart · KIPRIS |
| 보고서·제안서·IR·입찰서·HTML/PPT 제작 | 사업팀장 | Theme Factory · docx/pptx · 기존 스킬 호출 |
| 수치·인용·근거·일정·법령 적용 검증 | 감사팀장 | 사업팀장 산출물 전수 검사 |
| 이메일·카톡·외부 전송·고객 응대·일정 조율 | 민원팀장 | Whitelist 자동 발송, 고객은 사용자 승인 |
| 위 4개에 모두 걸리는 복합 과제 | 본부장 직접 분해 | 단계별로 4팀장에게 단편 위임 |

## 도메인 격리 원칙

- 본부장만 cross-domain 메모리 접근
- 4팀장은 자기 담당 작업의 도메인 폴더만 쓰기 가능
- 충돌 가능성을 원천 차단 (격리 모델)

## 권한 게이트

- 외부 발송 (고객): 사용자 승인 필수
- 외부 발송 (Whitelist 내부): 민원팀장 자율
- Git push (main 포함): 본부장 · 사업팀장 · 민원팀장 자율
- 결제/지출: 항상 사용자 승인

## 비용 가드레일

- 평소: 본부장 Opus 4.7, 팀장 4명 Sonnet 4.6
- 80% 도달: 팀장 4명 Haiku 4.5 자동 다운그레이드
- 100% 도달: 정기 cron 일시 정지, 사용자 호출 작업만 처리
